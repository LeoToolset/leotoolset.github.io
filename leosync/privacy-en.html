Privacy Policy – LeoSync

Last updated: November 11, 2026 · Version 1.3

This Privacy Policy explains what data is processed by the LeoSync Android app and how this data is handled.

LeoSync is an application developed under the Leo brand. It is designed to synchronize photos and videos between Android devices and user-owned network shares without relying on external cloud services.

1. Data Controller

Responsible for data processing:

  • Developer: [First and last name]
  • Country: Switzerland
  • Contact: leotools@protonmail.com

2. General Data Processing Principles

LeoSync has been developed with the principle of minimizing the transfer of data to external parties.

Photos, videos, metadata and synchronization information are generally processed locally on the Android device.

Files are transferred directly between the Android device and the SMB network share configured by the user.

LeoSync does not use:

  • External cloud storage services
  • Advertising networks
  • Analytics or tracking services
  • External synchronization services
  • Advertising or analytics SDKs

No usage statistics or personal data are automatically transmitted to the developer.

3. Photos and Videos

LeoSync requires access to the photos and videos selected by the user for synchronization.

The files are processed locally on the Android device and transferred directly to the configured SMB network share.

No files are transferred through a cloud service operated by LeoSync or its developer.

Depending on the selected synchronization mode, files may also be transferred from the SMB server to the Android device.

The transferred files are stored and managed at the storage locations selected by the user.

4. EXIF Metadata and Location Information

LeoSync can read GPS coordinates from the EXIF metadata of photos and supported video metadata.

This information is processed locally and compared with an integrated offline database to determine, for example, the country in which a photo or video was taken.

No external geolocation, mapping or location services are contacted for this purpose.

GPS coordinates are not automatically transmitted to the developer.

When original photos and videos are transferred, their original metadata may remain part of the transferred files.

5. Android Permissions

Depending on the Android version and the features being used, LeoSync requires certain permissions that must be explicitly granted by the user.

These permissions are used exclusively to provide the app's described functionality.

5.1 Access to Photos and Videos

LeoSync requires access to your photos and videos to process the selected media locally and synchronize them with the configured SMB network share.

Depending on the Android version, access can be granted to all media or restricted to selected photos and videos. The user decides which media access permissions to grant.

5.2 Access to GPS Metadata in Media Files

To read GPS coordinates stored in photos and supported videos for country detection, Android may require an additional permission to access location information contained in media files.

This permission only applies to location metadata stored in media files. It does not allow LeoSync to determine the device's current location.

All processing takes place locally and entirely offline on the Android device.

5.3 Location Permission for Wi-Fi Detection

Android links access to the name of the connected Wi-Fi network (SSID) to certain location permissions.

Therefore, LeoSync may require access to approximate or precise location information, as well as background location access.

These permissions are used exclusively by LeoSync to automatically detect the connected Wi-Fi network.

Background access allows this detection to continue even when the app is not open.

Depending on the Android version and device configuration, the setting "Location – Allow all the time" may need to be enabled.

Important privacy information: LeoSync uses the location permission exclusively for Wi-Fi detection. The app does not access the device's current GPS coordinates for this purpose and does not transmit the device's current location to the developer or external location services.

Country detection based on photos and videos is independent of this permission and uses only the GPS metadata stored in the media files.

5.4 Notifications

LeoSync may display notifications to inform users about ongoing and completed synchronizations.

On Android 13 and newer, the user must explicitly grant permission to display notifications.

Notifications are used exclusively to display information about the app's operation and synchronization status.

5.5 Background Operation and Battery Optimization

To ensure that synchronizations can run as reliably as possible even when the app is closed, LeoSync uses the background task mechanisms provided by Android.

Depending on the device and Android version, it may be necessary to exempt LeoSync from certain battery optimization restrictions.

For this purpose, the app may request an exemption in the Android settings. The user must explicitly approve this setting.

This setting is used exclusively to improve the reliability of background synchronization.

5.6 Installing App Updates

LeoSync may distribute updates directly as APK files.

Android may therefore require permission to install apps from this source.

The user grants this permission in the Android settings. The installation of each update must also be explicitly confirmed by the user.

This permission is used exclusively to install LeoSync updates and is not used to install other applications.

6. SMB Connections and Credentials

To connect to an SMB network share, LeoSync requires the connection details provided by the user.

These may include:

  • Server address
  • Share path
  • Username
  • Password
  • Additional connection parameters

SMB passwords are stored securely using the Android Keystore.

Credentials are not transmitted to the developer or external cloud services.

Files are transferred directly between the Android device and the configured SMB server.

Connection security also depends on the network configuration and security settings of the respective SMB server.

7. Diagnostic and Error Reports

LeoSync provides a feature for exporting technical diagnostic reports.

These reports are intended to help investigate errors, identify compatibility issues and improve application stability.

Depending on the implementation and the device, a diagnostic report may contain the following information:

7.1 Device and Application Information

  • Device manufacturer and model
  • Android version and SDK version
  • App version and build information
  • Manufacturer-specific system information

7.2 System Status and Permissions

  • Battery level and charging status
  • Battery optimization status
  • Power-saving and background execution status
  • Status of relevant app permissions
  • Available folder shares

7.3 Network and Synchronization Information

  • Wi-Fi connection status
  • Wi-Fi network name (SSID)
  • Network type and connection status
  • Synchronization settings
  • Configured synchronization profiles
  • Technical status of SMB connections
  • Synchronization history and error states

7.4 Technical Logs

  • Background tasks and WorkManager status
  • Warnings and error messages
  • Information about interrupted processes
  • Synchronization statistics
  • Timestamps of relevant events

Depending on the contents of the diagnostic report, it may also contain technical details such as Wi-Fi network names, local server addresses, share paths or file names.

SMB passwords are not intentionally included in diagnostic reports.

7.5 Pseudonymous Installation Identifier

Diagnostic reports may contain a randomly generated installation identifier (UUID).

This UUID:

  • Is generated locally on the device.
  • Is not derived from hardware or device identifiers.
  • Does not contain directly identifiable personal information.
  • Is used to associate multiple diagnostic reports with the same app installation.

A new installation identifier is generated when the app is reinstalled.

The UUID does not allow a person to be directly identified. However, since it can be used to associate multiple reports, it should be considered a pseudonymous identifier.

8. Sending Diagnostic Reports

Diagnostic reports are not transmitted automatically.

The user decides whether to export a report and send it to the developer by email.

The report is sent using the email application or email service selected by the user.

By sending a report, the technical information contained in it may be transmitted to the developer.

This may include Wi-Fi network names (SSID), local server addresses, share paths and device information.

Before sending a report, users should review its contents and consider that technical details may reveal information about their network and device environment.

The email provider's own privacy policy also applies to the processing of the email.

The developer uses voluntarily submitted diagnostic reports exclusively to investigate technical problems and improve LeoSync.

9. Third-Party Services and External Services

LeoSync does not use external analytics, advertising, tracking or cloud SDKs.

No user data is automatically shared with advertising or analytics providers.

Data may leave the device in particular in the following situations:

  • Synchronization with the SMB network share configured by the user.
  • Voluntary submission of a diagnostic report by email.
  • Technical checks for available app updates via GitHub Releases.

9.1 Update Checks via GitHub

LeoSync may periodically check whether a new app version is available. For this purpose, a connection to GitHub Releases is established.

During this request, technical connection information may be processed as part of a normal internet connection, in particular the IP address and information about the requested resource.

No photos, videos, GPS coordinates, SMB credentials or personal synchronization data are transmitted as part of this update check.

GitHub's privacy policy applies to the processing of technical connection data: GitHub Privacy Statement .

9.2 Data Transfers Initiated by the User

The Android operating system and any email or network services used by the user may process additional technical data as part of their own functions. The respective providers' privacy policies apply to such processing.

9.3 Statistics on This Website

This website counts page views and clicks on download, GitHub and language-switch links with GoatCounter, an analytics service without cookies. No profiles are built. Only the page visited, the language, the position of the clicked link and the release version are recorded. If "Do Not Track" or "Global Privacy Control" is enabled in your browser, nothing is sent. The LeoSync Android app itself sends no usage data.

10. Data Security

LeoSync uses the security mechanisms provided by the Android operating system.

In particular, stored SMB passwords are protected using the Android Keystore.

The transfer to the SMB server can be encrypted per profile (SMB encryption, SMB 3 or later). There are three levels: "Off", "If possible" (default) and "Required". With "Required", LeoSync only connects encrypted and does not send the user name or password if the server does not support encryption. Whether encryption is possible depends on the server.

The application is designed to avoid unnecessary data transfers and to perform processing locally wherever possible.

The security of file transfers also depends on the following factors:

  • Security of the local network
  • Configuration of the SMB server
  • SMB version used
  • Enabled authentication and encryption mechanisms

Users should appropriately secure their network shares and avoid exposing SMB services to the public internet without adequate protection.

11. Data Storage and Deletion

LeoSync does not operate its own cloud storage for user data.

Files are stored on the Android device and at the SMB storage locations configured by the user.

Local app data and settings can be deleted through Android's app management settings. When the application is uninstalled, its associated local app data is removed as part of the Android system process.

Files already transferred to an SMB share are not automatically deleted when the app is uninstalled.

These files must be managed directly on the respective storage device.

Diagnostic reports are initially exported locally. The developer only receives access to their contents when the user voluntarily sends them by email.

If the app crashes, LeoSync saves a crash report only locally in a file on the device. It is not transmitted automatically.

Profiles, settings and sync status can be exported to a file and imported again at the user's request. The file is saved locally at the location chosen by the user. Passwords are only included, encrypted, with an export password set by the user. LeoSync does not transmit this file itself.
